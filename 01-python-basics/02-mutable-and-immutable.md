# 可变对象与不可变对象

## 1. 本节定位

- 🔴 必须掌握：可变与不可变的定义、常见类型、共享引用的影响
- ⭐ 高频面试：元组中包含列表时，元组是否仍然不可变
- 🟢 项目基础：避免配置、检索结果和默认参数被意外修改

## 2. 核心结论

> 可变性描述对象创建以后，其自身状态能否改变，而不是变量名能否重新赋值。

- 常见可变对象：`list`、`dict`、`set`
- 常见不可变对象：`int`、`float`、`bool`、`str`、`tuple`

变量名可以重新绑定，这不代表原对象可变。

## 3. 可变对象

列表创建后，可以在不替换整个对象的情况下修改内部状态：

```python
chunks = ["A", "B"]
chunks.append("C")  # 原地修改同一个列表对象

print(chunks)  # ['A', 'B', 'C']
```

当多个变量引用同一个可变对象时，修改会被共同观察到：

```python
a = [1, 2]
b = a
a.append(3)

print(b)  # [1, 2, 3]
```

## 4. 不可变对象

字符串创建后，不能原地改变其内容：

```python
x = "RAG"
y = x
x = x + " System"
```

`x + " System"` 得到一个新字符串，再让 `x` 重新绑定：

```text
x ───→ "RAG System"
y ───→ "RAG"
```

整数同理：

```python
count = 10
count = count + 1  # 得到整数 11，并让 count 重新绑定
```

这不是把整数对象 `10` 原地修改为 `11`。

## 5. 元组嵌套可变对象

```python
data = ([1, 2], "RAG")
```

```text
data ─→ Tuple
         ├── index 0 ─→ List [1, 2]
         └── index 1 ─→ str "RAG"
```

元组不可变，指的是元组自身保存的元素引用不能被替换：

```python
data[0].append(3)  # 合法：修改元组元素所引用的列表
data[0] = [4, 5]   # TypeError：试图替换元组中的元素引用
```

第一行执行后，第 0 个元素仍指向原列表，只是列表自身变成了 `[1, 2, 3]`。因此，元组内部的列表可以变化，并不意味着元组本身可变。

## 6. 常见误区

### 误区一：变量能重新赋值，所以对象可变

```python
name = "RAG"
name = "Agent"
```

这里变化的是名字 `name` 的绑定，不是原字符串对象。

### 误区二：元组里的所有对象都不能变化

元组限制自身元素引用的替换；元素所引用对象的可变性由该对象自己的类型决定。

### 误区三：方法调用一定会原地修改

应查看方法语义。例如列表的 `append()` 原地修改，而字符串的 `replace()` 返回新字符串：

```python
text = "RAG"
new_text = text.replace("R", "T")

print(text)      # RAG
print(new_text)  # TAG
```

## 7. AI / RAG / FastAPI 场景

RAG 流程中经常传递列表和字典：

```python
metadata = {"source": "regulation.pdf"}
same_metadata = metadata
same_metadata["page"] = 10
```

两个名字引用同一字典，所以 `metadata` 也会出现 `page`。设计处理流水线时，要明确某一步是否允许修改输入，避免难以追踪的副作用。

## 8. 面试专区

### Q1：什么是可变对象和不可变对象？

> 可变对象创建后可以修改自身状态，例如 `list`、`dict`、`set`；不可变对象创建后自身的值不能修改，例如 `int`、`str`、`tuple`。列表调用 `append()` 会修改原列表，所以共享该列表的变量都能观察到变化。对 `int` 或 `str` 看似进行“修改”时，通常是得到新对象，再让变量重新绑定。

### Q2：元组中包含列表，元组还是不可变对象吗？

> 是。元组的不可变指其保存的元素引用不能被替换。如果某个元素引用列表，仍可修改这个列表。因此 `data[0].append(3)` 修改列表，而 `data[0] = [4, 5]` 试图替换元组元素，会报错。

### Q3：不可变对象有什么意义？

> 不可变对象的状态更稳定，更容易安全共享和推理。一些不可变对象在满足哈希规则时可以作为字典键或集合元素。

### 追问：`tuple` 一定可以作为字典键吗？

不一定。只有所有元素都可哈希时，元组才可哈希；包含列表的元组不能作为字典键。

## 9. 一分钟复习

- 可变性属于对象，不属于变量名。
- `list`、`dict`、`set` 通常可变。
- `int`、`float`、`bool`、`str`、`tuple` 不可变。
- 不可变对象的“修改”通常会产生新对象并重新绑定变量。
- 元组不能替换元素引用，但其引用的可变对象仍可修改。
